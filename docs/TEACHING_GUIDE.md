# Educator and researcher guide — make the idea tangible

The museum is a medium for explaining mathematics, not a requirement to simplify away its assumptions. Start with a single question a visitor can answer by doing something.

## A practical design sequence

| Step | Question for the author |
| --- | --- |
| Encounter | What can the visitor see or compare immediately? |
| Predict | What expectation can they express before calculation? |
| Manipulate | Which one or two parameters can they change? |
| Observe | What numerical or structural result changes? |
| Explain | What invariant, assumption or limitation accounts for it? |
| Reproduce | What independently computed reference could detect an error? |

Use a small bounded model first. Keep the mathematical state distinct from drawings. State units, coordinate conventions, coefficient fields and probability assumptions beside results. A schematic is not a proof. Label exact identities, floating approximations, hypotheses and fictional mechanics separately.

## Three worked lesson designs

**Geometry: same point, different address.** Use Quadray Workshop. Ask whether adding the same integer to each component moves the point. Let visitors change the offset and canonicalise. Show invariant Cartesian numerators and the explicit basis. Only then introduce the quotient-space language.

**Information: true does not mean new.** Use Observer Room and Evidence Ledger together. Reveal A and B, then A XOR B. Compare world counts and redundant evidence. Follow with Disclosure Theatre: the same final information set can produce different choices. State the model's maximin policy; do not equate it to Bayesian inference.

**Computation: convergence is not accuracy.** Use Message Tree, Hidden Tetrahedron, Contradiction Room and Inference Sweep. Predict which graph will match exact enumeration. Inspect residual and marginal error separately. Preserve the contradictory case as inconclusive. This makes the limitation visible without needing a general theorem first.

## From a notebook or paper to an exhibit

Extract a single reproducible claim, identify a public source or obtain permission, write a small reference case, define inputs and output, and select a supported template or native model. Separate a numerical reproduction from validation of the research assumptions. Include a counterexample or failure case, an explanation understandable without colour/audio, and optional deeper references.

For a seminar use a guided route from simple to complex. For a new model supply independent oracle tests and describe what would falsify your expected result. For an empirical run preserve units, settings, tolerances, outcomes and limitations. Export evidence; a reproduced record is not a scientific certification.
